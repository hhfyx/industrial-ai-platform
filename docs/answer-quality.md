## 〇、一页纸

### 首要结论：**卡了一整周的 P0 不是凭据问题，是本地请求走了系统代理**

| 客户端 | 走系统代理吗 | 打 `127.0.0.1:8326` 的结果 |
| --- | :---: | --- |
| `httpx` / openai SDK | **走（默认 `trust_env=True`）** | **502** |
| `urllib` | localhost 例外 | 200 |
| `http.client` | 不走 | 200 |

而 502 的 body 写着：

```json
{"error": {"message": "未配置凭据，请先登录"}}
```

**这个错误信息把排查完全带偏了。** 看起来是账号问题，实际是
Clash 之类的工具在系统里配了 `127.0.0.1:7897` 的代理，
openai SDK 把**本地回环请求**也扔进了代理。

> 我为此写了一个星期的"未验证"标注，甚至在 README 里把它列为 P0 阻断第 1 条。
> 真相是 `_build_client` 里少了一个 `http_client=httpx.AsyncClient(trust_env=False)`。

**修法（已落地）**：`app/core/llm/client.py` 的 `_build_client` 显式传
`trust_env=False` 的 httpx client。**不依赖环境变量** —— 那要求每个启动入口
（CLI / Streamlit / pytest / docker）都设对，漏一个就复现同样的假象。

## 二、三条错误逐条分析（这是最有价值的部分）

### 2.1 f-03：被阈值误拒 —— 分数闸门的真实代价

| 项 | 值 |
| --- | --- |
| 问题 | 容器里的运行时栈和运行身份是什么？ |
| gold | 非 root（uid 10001），Python 3.11 运行时 |
| 实际 | **`refused=True`**，答"知识库中未找到相关内容" |

**这是拒答阈值误伤的实证**：gold 块**在库里**（Recall 层面这条是命中的），
但 top1 分数低于 0.575，于是在生成前就被拦掉了。

> 这印证了 W5/W6 那条结论：**分数不含"能不能回答"这个信息。**
> 提高阈值能救拒答，但会拿真答案去换 —— 这条题就是被换掉的那个。

### 2.2 f-05：答非所问 —— 检索到了但没回答

| 项 | 值 |
| --- | --- |
| 问题 | 首字延迟这个指标的口径是怎么定的？ |
| gold | 从发起请求到第一个非空 content 的时间 |
| 实际 | 讲了"索引耗时不应算进问答延迟"，**没给 TTFT 的定义** |

**检索没错，是答案没落在问题上。** 这类错误最隐蔽：
引用有效、语气笃定、内容也来自上下文，**但不是用户问的那个东西**。

> 这类正是"引用只验编号存在"（P1-7）抓不到的：
> 引用 `[1]` 确实存在、那段话也确实是原文，**但它不支撑这个结论**。

### 2.3 f-10：选错判据 —— 相近概念的混淆

| 项 | 值 |
| --- | --- |
| 问题 | 三条人工判据里哪一条可以自动化到九成？ |
| gold | 判据一（块首块尾是否完整），能自动判定 90% |
| 实际 | 答"标题与内容是否分离"，**选错了那一条** |

上下文里三条判据都提到了，模型挑错了。这类要靠更强的上下文区分度
（或精排）来救 —— 但不能为此上 16.7 秒的精排。

### 2.4 两条"部分正确"

| id | 情况 |
| --- | --- |
| f-13 | 答对了 `data/chroma`，但前半句说"默认落在 `~/.cache/chroma`" —— **方向反了** |
| f-19 | 诚实说"材料未提到多进程共享加载"，但 **gold 的内容其实在库里** —— 这是检索没拿到，被模型误当成"材料没有" |

**f-19 值得单记**：它是"诚实地说没找到"和"真的没有"之间的混淆。
模型的行为是对的（不编），但**检索没给到材料**，用户会以为库里没有。

## 三、为什么多跳和拒答是 4/4，而事实型只有 7/12

| 题型 | 正确率 | 解释 |
| --- | ---: | --- |
| 多跳 4/4 | **100%** | 抽样只有 4 条，**1 条 = 25pp，不能当结论** |
| 拒答 4/4 | **100%** | 同上；且这 4 条里 3 条是模型自己判断"材料没有"，1 条是阈值拦的 |
| 事实型 7/12 | 58% | 样本最大、最有参考价值 |

**必须说清楚**：多跳 4/4 与检索层的"多跳 Recall@5 30%"**不矛盾** ——
这里是**分层抽样**（`strata: fact_hit 8 / fact_miss 4 / multi_hop 4 / refusal 4`），
不是按真实分布随机抽。**它不代表多跳的总体正确率。**

> 这正是"小样本 + 分层抽样"最容易骗人的地方。
> 报告里必须同时写 n 和抽样方式，否则 4/4 会被读成"多跳全对"。

## 四、局限（比数字重要）

| 项 | 状态 |
| --- | --- |
| **样本量** | 20 条。**1 条 = 5pp**，75% ± 会有很宽的置信区间（Wilson 95% 约 53%~89%） |
| **单次** | 每个问题只问一次，没有温度重复（无法区分"模型不稳定"与"检索不稳"） |
| **人工判定是单人** | 我自己判的，没有第二人复核。三处边界判断（f-13 / f-19 判 partial）有主观性 |
| **忠实度未单独量化** | 只看了"有没有幻觉引用编号"，**没做**"答案的每个断言是否都能在上下文里找到依据"的逐句核验 |
| **幻觉率未量化** | 3 条错误里 1 条是答非所问、1 条是选错、1 条是误拒 —— **这 20 条里没有典型的"凭空编造"**，但不能推导出"幻觉率 0" |
| **只测了最终链路（纯向量）** | 没测混合 / 精排 / 压缩那三组的端到端质量（它们默认关闭） |
| **单领域** | 语料是技术文档，**不可外推到工业/合同/工单** |

## 五、复现

```bash
# 走完整 20 条（约 20 次模型调用，成本约 ¥0.5~2）
python -X utf8 scripts/tasks.py answer-quality
```

**判定流程**（注意顺序，别弄反）：

1. 跑脚本 → 生成 `eval/results/answer-quality.json`，`verdict` 全为 `null`
2. **人工逐条填 `rows[].verdict`**（`correct` / `partially_correct` / `wrong` / `refused_wrongly`）
3. 需要汇总时……**不要再整跑一遍**

> ### ⚠ 这一步我踩过坑
> 第一版脚本每次运行都重新生成 `rows`，于是"为了看汇总再跑一次"会把
> **刚填好的 20 条判定全清空**。我已改成"输出文件存在时，按 `id` 搬回人工判定列"。
>
> 这个错误很典型：把"重新采样"和"重新汇总"混成一个命令。
> 如果没发现，结果就是**判一次白判一次**。

## 六、对 W7 的直接影响

1. **终于可以写"问答正确率"了** —— 但要写全：`75%（n=20，严格正确，单次，单人判定）`
2. **拒答要从生成层做**：f-03 证明阈值会误伤真答案。
   方向是"让模型看到材料后自己说没找到"，而不是"分数低就不给材料"。
3. **引用校验要升级**：f-05 那种"引用存在但不支撑结论"是当前 LCS 弱校验抓不到的。
4. **120 条评测集要把"答非所问"单列一类** —— 它和"编造"完全不同，修法也不同。
