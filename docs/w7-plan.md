### 0.3 算术

```
现有密度：50 条 / 13 份 ≈ 3.8 条/份
若同样密度覆盖 26 份 → 约 99 条        ← 这是"自然扩展"的上限
要到 200 条          → 平均 7.7 条/份  ← 密度要翻倍
```

**所以问题的答案取决于一件事：能不能在 26 份文档里出到 7.7 条/份的密度？**

### 0.4 密度可行性：按题型估

| 题型 | 每份能出几条 | 26 份合计 | 依据 |
| --- | --- | ---: | --- |
| 事实型（锚点唯一） | 3~5 | 78~130 | 每份文档有 20~128 段，中等长度段落都能出 1 条 |
| 多跳（跨 2 段） | 1~2 | 26~52 | 段数 ≥20 的文档才有足够的"两处呼应"素材 |
| 拒答（库外知识） | 不限 | 40 | 不依赖语料，从"同领域但库里没有"的知识出题 |
| **合计** | | **144~222** | |

**结论：200 条在理论上是够得着的，但处在区间上沿** ——
需要 130 条事实型 + 30 条多跳 + 40 条拒答。

**风险**：事实型要出到 130 条（平均 5 条/份），而 `release-notes-v0.3.0.md`（8 段）
这种短文档，出 5 条会非常勉强。

## 一、三条可选路线

### 方案 A：降到 120 条（**推荐**）

| 项 | 值 |
| --- | ---: |
| 条数 | 120（80 事实 + 20 多跳 + 20 拒答） |
| 密度 | 约 4.6 条/份 |
| 对比现有 | 与现有 3.8 条/份接近，**不需要压榨短文档** |
| 统计效力 | 120 条上 1 条 = 0.83pp（现在 50 条是 2pp） |

**理由**：宁可要 120 条**每一条都认真标**，也不要 200 条里有一半是凑的。
而"凑出来的题"的危害是：**它会污染归因** —— 你会以为某个改动无效，
实际是那道题本身标得不对。

**统计上的收益已经很显著**：1 条从 2pp 降到 0.83pp，
意味着 W6 那些"差 1~2 条"的结论（比如精排 +15pp）终于能被判定了。

### 方案 B：200 条 + 扩语料（**更彻底，但今天开始不了**）

引入**真实外部文档**（公开合同、工单、技术规范）：
- 好处：彻底解决"自造文档只有 26 份"的结构问题，且能验证"工业文档上 BM25 收益更大"那个未验预期
- 代价：需要找合规的公开语料 + 重新跑全部锚点 + 现有 50 条全部重标
- **现实判断**：这属于 W8 的活，不是这周能做完的

### 方案 C：硬凑 200 条（**不推荐**）

在 26 份文档上压榨到 7.7 条/份。后果：
- 短文档（8 段、7 段）要出 5 条以上 → 题目会变得极其细枝末节
- 同一段落被问 2~3 遍（换个问法）→ **这是"假互不重叠"**
- 而 eval-50.md 立的第一条规矩就是"**题面不得重复，哪怕换个问法**"

### 2.2 与现有 50 条的关系

**严格不重叠**，且按 eval-50.md §〇 的规矩做模糊去重：

```python
# 伪代码：出题时的去重检查
for new_q in new_questions:
    for old_q in questions_50:
        assert similarity(new_q.question, old_q.question) < 0.8
        assert new_q.anchor.source != old_q.anchor.source  # 强制换文档
```

**更强的一条**：**新题优先从"从未出过题的 13 份"里出**。
那样连"同一份文档反复出题"的问题都避开了。

### 2.3 出题顺序建议

1. **先出 60 条**（覆盖 13 份新文档）
2. 跑一次基线，看这批题的难度分布是否合理
3. 再出 60 条（补齐配额）
4. 最后做一次"全 120 条 vs 现有 50 条"的交叉检查

**为什么分两批**：一次性出 120 条，如果难度整体偏了（比如全是简单题），
返工成本是 120 条。分两批返工成本是 60 条。

## 四、本文结论

| 问题 | 答案 |
| --- | --- |
| 200 条会不会撞语料瓶颈？ | **处在临界** —— 理论够（144~222），但需压榨短文档 |
| 建议 | **降到 120 条**，理由：密度合理 + 标注质量优先 + 1 条 = 0.83pp 已足够 |
| 语料要扩吗？ | 这周不扩；**W8 若引入真实文档，可再升到 200** |

**一句话**：不是"13 份文档出 200 条不可能"，
而是"**在不凑数、不重复问法的前提下，26 份文档能支撑到 120 条左右**"。
