## 二、本周最大的坑：SequenceMatcher 的 autojunk 静默失效

**周二去重模块，现象**：两段共享 195 字的文本（近重复无疑），
`SequenceMatcher.ratio()` 返回 **0.0**。

**为什么危险**：不是报错，是**返回一个"看起来合理"的 0**——
如果我没有写"合并后 near_removed 必须 == 1"的断言，
去重层就会永远不工作，而测试全绿、功能"正常"。
近重复检测整个失效，且没有任何信号。

**根因**：`autojunk=True`（默认）把"出现频率 > 1% 的字符"当垃圾元素——
但那是对**英文长序列**的启发式。中文块动辄数百字，"的、是、按"这些高频字
远超 1%，整个文本被判成垃圾。**这是标准库启发式在中文语料上的静默失效**，
网上中文资料极少（大家都用英文语料）。

**修法**：`autojunk=False`，一行；共享 195 字回到 ratio 0.9+。
**教训**：任何"默认参数的智能启发式"在换语料时都要重新怀疑一遍。
它与 W3 的 `connect_ex` 反用、W7 的 tasklist CSV 是同一族：
**验证手段本身会错，且错的时候不报错。**

## 三、第二深的印象：部署版和评测版不是一回事（口径的灵魂）

周六在容器里跑通全链路后，最诱人的动作是把 Recall@5 56.0% 抄到 Cloud 链接旁边。
**但 Cloud 是 hashing**——56.0% 是 bge FP16 + chunk500/overlap50 的数字。

写 deploy-variant.md 时的自问自答把口径钉死了：
**三条形态一张表、每个数字对号入座、简历三条红线**（不要把评测数字标在
Cloud 链接旁 / 不要说线上是语义检索 / 不引用未实测数字）。
面试被问"部署版和评测版差在哪"，答案就是那张表——
**这不是防御，是把"知道自己边界"变成可展示的资产。**

## 四、本周方法论四条

1. **"能起"≠"能跑"≠"能答对"是三件事**。GPU 镜像 build 成功（能起）→
   openai 缺模块（不能跑）→ LLMSettings 崩（不能跑）→ volume 属主（不能答）。
   每层都在 Dockerfile/compose 上修了一行，但**发现它们的成本远高于修复成本**
   ——容器问题必须在容器里验证，本地全绿不算数（W7 的第 3 坑第三次应验）。
2. **fallback 必须可见**。structured_call 的 fallback 降级是静默返回，
   改写层用 `result is fallback` 判别身份才把 degraded 标出来。
   静默降级 + 不可见的产物 = 归因时把"没生效"误读成"能力差"。
3. **先立契约再提速**（周三必答问题的实践版）。同步版一天立住契约/错误码/单测，
   异步版只是给同一份契约套 202+task_id——周四的异步化因此没有长出
   任何新的错误格式。
4. **数字要么实测、要么留空格子**。generator-benchmark 的表格里
   "待真权重实测"的格子就是空着——写"约 1.8s"比写"待测"危险一百倍。

## 七、W9 要证明什么

**Agent 能用工具完成多步任务**。W8 已把工具箱备齐：
`retrieve(query, k)`（W6 冻结）、`generate(question)`、`rewrite(question, history)`——
W9 的 Agent 层要证明的不是"能调一个函数"，而是：

1. **多步**：一个复杂问题 → 拆解 → 两次 retrieve → 合并上下文 → 一次生成；
2. **失败自愈**：检索空/低分时 Agent 决定改写重试，而不是把空上下文塞给模型；
3. **边界守住**：Agent 调工具走的是**注册表 + 权限边界**（W2 的结论：
   执行永远在我这侧），不是裸的 eval——改写层不该被 Agent 绕过（周一红线）。

W7 的归因说"检索未召回 53%"——W9 的 Agent 如果能在检索失败后自主改写重试，
那 53% 里的一部分就是 Agent 层的直接收益。这是 W9 的叙事主线。

## 八、W9 预习（只读不动手）

- W2 的 tool_loop：`tool_calls` 回灌闭环已实现，注册表即权限边界——Agent 层复用它，
  不重写循环；
- 需要新工具 schema：`retrieve` / `generate` / `rewrite` 三个，description 按
  W1 结论写"什么时候该用"；
- 生成服务的异步队列（W8 周四）是 Agent 调 generate 的正确入口
  （202+轮询），同步版只适合单张。
