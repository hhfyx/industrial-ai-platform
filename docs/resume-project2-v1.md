## 工业级 RAG 检索问答系统（个人项目，10 周，Python/PyTorch/Streamlit）

**一句话**：从零构建 RAG 全链路（切分 → 向量/BM25 混合检索 → Cross-Encoder 精排 → 引用式生成），并以自建 120 条黄金评测集完成量化评测与失败归因；全程指标可复现（代码指纹 + 参数指纹 + 口径冻结）。

### 核心数字（全部实测，口径见括号）

- **检索 Recall@5 56%**（120 条黄金集，fact 66% / 多跳 15%，冻结口径：任一锚点进 top5）
- **端到端答案得分 0.66**（100 条可答题，LLM judge 三档判定，judge 与人工一致率 30/30）
- **失败归因四类占比**：检索未召回 53% / 多跳跨块 22% / 生成问题 16% / 术语未命中 9%
  （100 条逐条归因；**答对率随检索层单调下降 67%→38%→15%**——检索质量决定生成上限的量化证据）
- **四层消融**：精排 +17.5pp Recall@5，代价延迟 119ms → 17.5s（×147）（40 条 × 4 配置，1165 块语料，CPU）
- **混合检索（RRF）−5pp**：用机制解释推翻了"加上就好"的直觉——RRF 偏好共识候选，而两路候选独有占比 86%（40 条 × 8 组对照，全部 p>0.05，不显著即不上线）
- **974 条离线测试**（拔网全绿，50s），覆盖口径恒等式、语料/参数指纹护栏、跨集泄漏检测

### 工程亮点（面试可深挖）

1. **评测集防污染**：调参集（80 条）与报成绩集（120 条）物理分离 + 机器隔离门禁
   （相似度/换问法去重测试），题源只出自 13 份从未出过题的文档
2. **指标防刷设计**：每个指标先写"会被怎么刷"再实现（Recall 防标宽锚点、
   MRR 防选择性报告、拒答三分类防合数掩盖权衡）；judge rubric sha256 冻结防事后放宽
3. **拒答阈值无解的证据**：可答/拒答 top1 分数完全重叠（[0.513, 0.629]），
   单阈值双爆（误拒 12 + 幻觉 14）——用数据否定了"调参能修"，指向二段判定方案
4. **全链路可复现**：一条命令出全部指标（`make run-eval`），报告携带
   commit hash + 参数/语料指纹 + 口径版本；CI 内置零成本评测冒烟
