# 错例归因表（W6 周日重写）

> **这份表推翻并重建了 W5 的归因结论。**
> 数据：`scripts/error_attribution.json`｜命令：`make attribute-errors`

---

## 〇、一句话

**W5 的「② 术语/同义词未命中」占了 50%（15/30），而它是一条错的标签 ——
那 15 条里 0 条含稀有标识符。** 重写后 ② 是 **0 条**，
原来的问题被拆成 ⑤ 长块（8）、⑦ 语义区分度（6）、⑥ 零交集（1）。

---

## 一、为什么旧标签是错的

### 1.1 旧判据的本质：② 是**默认分支**

旧版 `classify()` 的判断链：

```
不是拒答？ → 不是多跳？ → 不是表格？ → 不是块尾半句？ → **② 术语未命中**
```

最后那个 `return` 就是默认兜底。于是"我没想清是什么原因"的题**全部变成了"术语问题"**。

这不只是分类不准，而是**把"未知"伪装成了"已知"** ——
它会让后续所有改进动作都朝"修分词器/加词典"去，而那些题根本不吃这一套。

### 1.2 W6 周一的数据：0 条含稀有标识符

对那 15 条逐条查"query 与 gold 块有没有稀有公共 token"：

| 检查结果 | 条数 |
| --- | ---: |
| 含稀有标识符（`INVALID_INPUT`、`bge-small-zh` 这类） | **0** |
| 只共享「模型/输入/上限/文档」这类高频普通词 | 12 |
| 连一个公共 token 都没有 | 3 |

**"术语未命中"这个说法暗示"加个更好的分词器就能解决"，
而 0 条含稀有标识符说明那条路对这批题无效。**

### 1.3 W6 周六的验证：混合检索救回 0 条

把 BM25 + RRF 接上去，再测那 15 条：

```
f-01 … f-30：纯向量未命中，混合也未命中
=> 救回 0 条，丢失 2 条（f-16、m-09）
```

W5 §5.2 提前写下的可证伪判据是：

> **如果只救回 1~2 条** → 假设错了。那 15 条的主因不是"词没匹配上"，
> 而是别的（可能是分数区分度不足、或 gold 本身选得偏）。
> **那时要回头改归因表，而不是继续调 RRF 权重。**

**实测 0 条，判据明确指向"假设不成立"。**

> 两条独立证据链（周一逐条判定 + 周六端到端验证）指向同一结论。
> W5 当时那句话写得对：**"改归因表比调权重更需要勇气，但那才是诚实的动作。"**

## 二、新判据：按"字面锚点的稀有度"分类

| 新类别 | 判据（可机判） | 该谁修 |
| --- | --- | --- |
| **① 切分断语义** | gold 块以半句结尾（剥掉 Markdown 分隔线后判） | 切分器 |
| **② 术语未命中** | **仅当含稀有标识符却仍排不上** | 分词器 / 词典 |
| **③ 多跳需跨块** | 多锚点且有缺失 | 跨块合并 / 两轮检索 |
| **④ 问题本身模糊** | **机器判不了**，留人工 | —— |
| **⑤ 长块被挤掉** | gold 是表格块，或显著长（≥400 字）且不在 top50 | 长块降权 / 表格路由 |
| **⑥ 字面零交集** | query 与 gold 块**零公共 token**（剔虚词后） | 查询改写 / 向量侧 |
| **⑦ 语义区分度不足** | 有公共 token 但全是高频虚词/单字 | 更强 embedder / 精排 |

**⑤⑥⑦ 是这次新拆出来的** —— 它们原本都挤在 ② 里，而三者的修法完全不同。

### 3.1 三类的具体修法差别

| 类别 | 8 条 / 6 条 / 1 条 的真实含义 | 该怎么修 |
| --- | --- | --- |
| **⑤ 长块（8 条）** | 全是表格块（`metadata.block == "table"`），长度 154~431 字 | 长块降权 或 表格单独路由 —— **不动切分器** |
| **⑦ 区分度（6 条）** | f-05 f-08 f-10 f-19 f-20 f-30：共享「指/返/模/限」这类字，但不够区分 | 换更强 embedder 或加精排 —— **不动分词器** |
| **⑥ 零交集（1 条）** | f-25（CoT 提示代价）：英文与中文完全不搭 | 查询改写（术语对齐） |

**三类修法互不相同，混在一个"术语未命中"里必然做错方向。**

## 四、重写过程中又抓到两个判据 bug

### 4.1 Markdown 分隔线被当成"半句"

`looks_truncated()` 第一版直接看块尾最后一个字符。
实测 f-08 / f-10 / f-27 的块尾是 `\n\n---`（Markdown 分隔线），
于是它们被判成"① 切分断语义"—— **① 类从 2 条虚增到 4 条，其中 2 条是误判**。

**分隔线不是句子内容。** 块尾落在分隔线上说明**切在段落边界上**，
那恰恰是切分器工作正常。修法：判之前先剥掉 `---+` / `***` / `___`。

### 4.2 中文切词正则把整句吃成一个 token（更严重）

`_WORD` 第一版写的是 `[一-鿿]+`（带 `+`），于是：

```
"模型的输入长度上限是多少"  →  ['模型的输入长度上限是多少']   ← 一个 token
```

**后果：任何中文 query 与中文块的交集恒为 0。**

这意味着判据里的 ⑥（零交集）会吞掉**所有**中文错例，
而 ②（术语未命中）**永远不可能触发** —— **整套判据失效**。

修法：去掉 `+`，中文按单字切；并加一份单字停用表剔除「的/是/在/个」这类虚词
（否则任意两句都会共享虚字，"零交集"判不出来）。

> **这两个 bug 有一个共同点**：都是"判据看起来在工作，但测的不是我以为的东西"。
> 和周五压缩那两个 bug 是同一类 —— **先验证基线，再相信结果。**

## 五、这对 W7 意味着什么

### 5.1 W7 出 200 条题时，必须按新类别分布配额

旧表的 50% 是"术语未命中"，如果按那个分布设计评测集，
会有大量题落在"词典能解决"的假设上 —— 而那个假设已经被证伪。

**建议配额**（按今天的真实分布）：

| 类别 | 建议占比 | 理由 |
| --- | ---: | --- |
| ⑤ 长块/表格 | ~25% | 本项目表格块 320 个，覆盖不足（W5 就记过"0 条表格题"） |
| ③ 多跳 | ~20% | 现有多跳只有 10 条，1 条 = 10pp，统计上太脆弱 |
| ⑦ 语义区分度 | ~20% | 这是"换 embedder / 加精排"的主战场 |
| 拒答 | ~20% | 阈值问题的唯一验证场 |
| ① 切分断语义 | ~10% | 需要真的构造长句跨块的题 |
| ⑥ 零交集 | ~5% | 同义改写类 |

### 5.2 归因表现在是"可重跑"的

之前 `error-cases.md` 里人工填的两列一直是 `_待填_`。
现在**自动判据能给出候选 + 依据**，人工只需要复核（而不是从零填）。

这不等于"不需要人工" —— ④（问题模糊）机器判不了，
⑤⑥ 的重叠情况（表格块常常同时零交集）也需要人定夺。

## 六、局限

| 项 | 状态 |
| --- | --- |
| ④ 问题本身模糊 | **仍未覆盖**（机器判不了，需要人工读语义） |
| ⑤ 与 ⑥ 的重叠 | 表格块 8 条里 6 条同时"零交集"，现在优先判 ⑤ 并在 signals 里标注 ⑥ 的可能 |
| 中文按字切 | 粗粒度近似，会漏掉"整词才匹配"的情况（但比"整句一个 token"好得多） |
| 样本量 | 30 条错例，1 条 = 3.3pp；占比只应看量级，不宜精确解读 |
