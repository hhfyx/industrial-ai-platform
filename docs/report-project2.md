# 技术报告二：文档知识库 RAG 平台（检索 → Agent → 可观测 → MCP）

> W14 周三产出。数字带台账编号（`docs/w14-number-ledger.md` #n），
> 命令可在仓库根目录复跑。页脚有 commit hash 与日期。

---

## 1. 背景

目标：把散落的工程文档（Markdown/PDF）变成一个**可问答、可核查、可运营**的
知识库服务——答案带引用、拒答有依据、成本可对账、故障可下钻。

约束与取舍（每条都对应一个实测决策）：

| 约束 | 决策 | 证据 |
| --- | --- | --- |
| 部署目标是免费层（1GB 内存） | Cloud 版降级 hashing 检索，降级在 UI 显式可见 | deploy-variant.md 三形态对号表 |
| 精排有效但慢 140 倍 | 默认关闭，保留实测数据 | 台账 #23–24 |
| 简历每个数字要可对号 | 三形态口径表先于任何宣传 | 台账 §七口径隔离表 |

---

## 2. 架构与链路

```
PDF/MD → 解析（标题启发式）→ 切分（chunk=500/overlap=50, recursive）
      → 索引（bge-small-zh FP16 / hashing 双形态）
      → 检索（向量 ⊕ BM25 → RRF 融合）
      → [可选] Cross-Encoder 精排 → [可选] 句子级压缩
      → 生成（引用完整性：chunk_id 去重 + 双向校验）
      → Agent 层（LangGraph：四工具 + 检查点 + 人机中断）
      → 服务层（FastAPI：鉴权/限流/缓存/幂等）
      → 可观测（trace 三级 + 指标层 + 对账）
      → MCP（工具面标准协议暴露）
```

**链路上每个"可选"都是实测后的默认关闭**——精排 +22.5pp 但 p50 17,514ms
（台账 #23–24）；压缩省 42.4% token 但不改变检索指标（#26，按设计）。

## 3. 消融表（1165 块口径，含代价列；台账 #21–28）

> 本报告只引 1165 块重跑口径。1592 块旧表保留在原文档作历史对照，**不进材料**。

| 组（40 可答 + 10 拒答） | Recall@5 | MRR | p50 延迟 | 上下文 tok | 代价 |
| --- | ---: | ---: | ---: | ---: | --- |
| ① 朴素向量 | 40.0% | 0.2577 | 119 ms | 689 | 基线 |
| ② +混合检索 | 35.0% | 0.2902 | 122 ms | 685 | +BM25 索引 755ms；Recall@5 **−5.0pp**（RRF 挤掉独有召回） |
| ③ +精排 | **57.5%** | 0.4370 | 17,514 ms | 949 | +Cross-Encoder 2.27GB；延迟 ×~140；**p=0.0703 未达显著** |
| ④ +压缩 | 57.5% | 0.4370 | 17,514 ms | 547 | 省 42.4% token；检索指标 +0.0（按设计） |

两个负结果如实进报告：混合检索在本语料结构上 Recall@5 反降 5pp；
精排 +17.5pp 方向明确但 40 条样本未达统计显著（p=0.0703）——写"方向明确"，
禁写"显著提升"（台账 #25）。

## 4. 评测体系

**规模**：120 条黄金集（80 事实 + 20 多跳 + 20 拒答），13 份文档出题、
与 40 条 prompt 实验集零重叠、quote 脚本取证杜绝手抄错（台账 #15）。
**所有"200 条"历史表述一律以 120 为准**（w7-plan.md 定案）。

| 环节 | 做法 | 结果 |
| --- | --- | --- |
| 口径冻结 | 指标定义先写"怎么刷"；rubric sha256 冻结 | 出题期零返工 |
| judge 校准 | 人工先判后对（30 条），一致率 **30/30** | 锚定风险由"理由全落盘 + 30% 人工复核"缓解（台账 #5） |
| 全量评测 | `run_eval.py` 一条命令，分母硬断言 | Recall@5 **56.0%**（100 可答题）；fact 66.2% / 多跳 15.0%（差 51pp，最稳健结论） |
| 拒答 | 单阈值扫描 | 正确拒 6/20、误拒 12、幻觉 14；**可答 top1 最低 0.513 与拒答 top1 最高 0.629 区间完全重叠**——特征不具备可分性，单阈值无解是数据逼出的结论 |
| 归因 | 四类 + 分层表 | 检索未召回 53% / 多跳 22% / 生成 16% / 术语 9%；答对率随检索层 67%→38%→15% 单调下降 |

**归因审计救回一次方向错误**：初判"生成问题 66%"，读 judge 理由文本发现
16 条其实是"检索没把材料送到"——重新归类后检索类合计 53%，
W8 的改进方向因此从修生成改为修检索。归因不能只看标志位笛卡尔积，
必须读文本。

## 5. 可靠性（Agent 层，W11）

| 机制 | 设计 | 实测 |
| --- | --- | --- |
| 五类错误分类 | 参数错/权限错/超时/空结果/内部异常；每类定"可恢复吗、谁恢复、几次、用尽后" | `retryable` 由代码判定而非模型猜 |
| 重试/降级矩阵 | 不可重试错误一律不给退避秒数 | 测试固住 |
| 20 任务评测 | 10 回归 + 10 新增，判据冻结 01-01；**降级计入失败** | 成功率 **70–100% 区间**（5 轮：18/20→20/20→14/20→17/20→19/20）；12 稳过/0 稳败/8 波动（台账 #29–30） |
| 编造审计 | 口径=答案数值在成功工具返回里找不到出处；轨迹 `evidence_numbers` | **0 例**（6 个不可完成 × 5 轮）；判据曾误伤"有出处的引用"（T10/N11），已区分——写 0 必须同时交代这个（台账 #32） |
| 预算与早停 | token/步数/墙钟三道上限 | 拐点 **10k**（5k=50%/10k=83%/15k=83%，15k 多花 9.3% token 零收益）；**早停本轮收益为 0**，如实报（台账 #35–36） |

**三次"把好事弄坏"**：确认约束误用于全局 / 10k 预算截断即将给出的正确答案 /
降级语义过宽连坐已完成任务——同构教训：**可靠性机制的风险不是不生效，
而是生效得太广**。

## 6. 可观测（W12–W13）

| 层 | 实现 | 验证 |
| --- | --- | --- |
| trace 三级 | trace→span→generation；一次请求 12 个 span；错误/取消 100% 保留，正常按采样率 | 慢请求下钻实测：根 span 120ms=chaos 注入，检索段 0–1ms |
| 指标层 | `usage_ledger` 逐笔直录（只 INSERT）+ `metrics_hourly` 聚合 | 台账 #3：280 笔直录 / 1.4656 元实算 |
| **成本对账** | 聚合侧 vs 直录侧逐 token 比对 | **抓出两个真缺口**：extract 漏埋点成本低估 45%；两套单价表同一调用两个价（cost_diff=1.0） |
| 告警 | 4 条规则，阈值全部有实测出处（检索 P95 20ms = W12 基线 10ms × 2，非行业默认 3s） | `test_rules_have_rationale` 固住"没有 rationale 的规则不许存在" |
| 压测 | 五档 × 两轮（差 <4%）；429 计 success 不计 failure | 27.3 QPS（20 并发）、P50 3–4ms 恒定、错误率 0%、5xx=0、A3 429 占 55.7%=限流配额在挡（台账 #37–40，**hashing 热缓存口径**） |

**压测里最有价值的产出是一条失败的优化**：分段表说序列化占 50%，
照做响应瘦身+缓存——归因矩阵三组实测全部在噪声内。教训：分段表告诉你
哪段最贵，不告诉你那段为什么贵；优化前必须先确认成本随什么变量变化。

## 7. MCP（W13）

| 项 | 做法 |
| --- | --- |
| 协议分工 | 行为层（fs 工具纯函数 + W11 错误信封，不 import mcp）/ 协议层（`_unwrap`）分离——测试不依赖 SDK |

| 攻击测试 | **5 条全拒**且 error_type 可读；过程中修复两个真实盲区：Windows 上 `/etc/passwd` 的 `is_absolute()=False`；字符串前缀假象（resolve 纪律钉测试） |

## 8. 已知局限

1. **评测全是小样本**：120 条 / 20 任务 / 40 条消融——方向性结论可靠，
   单点百分位不可外推；跨域未验证。
2. **形态隔离**：56.0% 属评测版=容器版；Cloud 线上是 hashing 字面检索，
   拒答闸门关闭（阈值 0.0）；bge 形态未压测。三形态数字不得互串（台账 §七）。
3. **成功率的区间本质**：5 轮 70–100%，最好一轮 100% 是一次抽样不是结论；
   稳定性只跑 3 次（95% 置信下界 ~0.37）。
4. **判据已知缺陷**：不可完成任务用"不许出现库内数值"防编造，
   无法区分"编造"与"引用查询结果做对比"，判据因冻结未改，行为侧已缓解。
5. **Claude Desktop 接入未做**（自写 host 覆盖同一验收语义）；
   队列深度告警未进 RULES；浸泡测试未做（3–4 分钟窗口验证不了慢劣化）。

## 9. 复现命令

```bash
# 检索基线（50 条集，零成本）
python -X utf8 scripts/run_retrieval_eval.py
# 四配置消融（约 12 分钟）
python -X utf8 scripts/tasks.py ablation-four
# 全量 120 条评测（花钱，约 15 分钟）
python -X utf8 scripts/tasks.py run-eval --questions eval/questions-120.jsonl
# 简历数字总核对（从原始产物重算）
python -X utf8 scripts/verify_resume_numbers.py
# 数字台账一键复现（零成本）
python -X utf8 scripts/tasks.py report-numbers
# 压测（需 :8100 服务在线，约 17 分钟）
python -X utf8 scripts/load_test.py --profile all
```
