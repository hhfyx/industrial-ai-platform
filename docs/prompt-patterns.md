## 必答题：CoT 让准确率变好了还是变差了？

**在这个任务上，CoT 提示让准确率变差了 ——（几乎是）零收益、负代价。**

而且要分成两件事说清楚，因为它们的结论**不一样**：

| 问的是什么 | 对照 | 结果 |
| --- | --- | --- |
| **Prompt 里要求「先写理由」有没有用** | E vs A | 全线归零：12/20 → 12/20（+0.00），字段级 0.867 → **0.850**（−0.017） |
| **模型自带思维链有没有用** | F vs A | 微弱有效：12/20 → 13/20（+1 条），字段级持平 0.867 |
| **在已有思维链的模型上再加 CoT 提示** | G vs F | **明确变差**：13/20 → 12/20（−0.05），字段级 0.867 → **0.850** |

### 为什么变差（三条，都有数据支撑）

**1. 这是推理模型，思维链本来就在跑；再加 CoT 提示是让同一个动作做两遍。**

本次用的 `deepseek-account/deepseek-flash` 网关元数据写明默认 `reasoning=high`。
我把它显式打开（F 臂）后，平均产出 **539 字符**的思维链；再叠加「先写理由」的提示
（G 臂），思维链涨到 **1224 字符** —— 翻了 2.3 倍。也就是说模型并没有"想得更深"，
而是把已经想过的判定规则**用中文再复述一遍**。

**2. 多出来的那部分不是推理，是自我说服；它把原本正确的边界判断推歪了。**

token 账很好算：

| 臂 | 平均 completion token | 相对 A |
| --- | ---: | ---: |
| A zero-shot | 21 | 1× |
| E（CoT 提示，关闭推理） | 108 | **5.1×** |
| F（自带思维链） | 172 | **8.2×** |
| G（两者叠加） | 888 | **42×** |

花了 42 倍输出 token，换来的是**准确率下降**。

更关键的是**错在哪个字段**。三个臂的字段级错误分布：

| 臂 | 问题类型 错 | 紧急程度 错 |
| --- | ---: | ---: |
| A zero-shot | 1 | 7 |
| E CoT 提示 | 2 | 7 |
| F 自带思维链 | 3 | 5 |
| G 叠加 | 2 | 7 |

**「紧急程度」是硬骨头**（20 条里错 5–7 条），而 CoT 恰好在这上面一点没帮上忙。
逐条看几个典型：

| 条目 | 金标 | A（直答） | E（CoT 提示） | F（自带思维链） |
| --- | --- | --- | --- | --- |
| #4 App 闪退 | P2 | P1 ✗ | **P2 ✓** | P1 ✗ |
| #5 充值未到账 | P0 | P1 ✗ | **P0 ✓** | **P0 ✓** |
| #8 到达率下跌 | P1 | **P1 ✓** | P2 ✗ | **P1 ✓** |
| #10 报表数据全 0 | P1 | **P1 ✓** | P0 ✗ | P0 ✗ |

这是**此消彼长**：CoT 让它对 #4/#5 这类"有资金风险 / 有明确绕过方案"的题判得更准，
却又把 #8/#10 这类"看起来严重但实际可绕过"的题**抬高**成 P0。模型一旦开始长篇论证，
就会倾向于把话说重 —— 这是 CoT 在**分级判断**上的典型副作用：它鼓励模型在不该升级的地方升级。

**3. 代价还落在延迟上，且是用户能感觉到的。**

| 臂 | 平均延迟 | 相对 A |
| --- | ---: | ---: |
| A | 724 ms | 1× |
| E | 1476 ms | 2.0× |
| F | 1681 ms | 2.3× |
| G | **6209 ms** | **8.6×** |

工单分类是**在线链路**（客服系统实时打标）。8.6 倍延迟换 −5pp 准确率，产品上不可接受。

### 一个必须说清的坑：我差点得出错的结论

G 臂第一次跑（`max_tokens=1200`）时出现了 3 条 `finish_reason=length`，
`content` 为 `None` → 解析失败 → 判 0 分，G 看起来只有 9/20。

**如果不查 `finish_reason`，我会把这 3 条算成"CoT 让模型变笨"，那就是假归因。**
把预算提到 3000 重跑后，这 3 条都正常输出（#7 用了 1725 token、18 秒），
准确率回到 12/20。**所以「G 变差」是真的，但幅度是 −1 条，不是 −4 条。**

> 这条教训和 [`01_params.md` §3](01_params.md) 是同一个：
> `finish_reason == "length"` 才是截断的唯一判据，不能看内容长度猜。

## 一、实验条件

| 项 | 值 |
| --- | --- |
| 端点 | `http://127.0.0.1:8326/v1`（OpenAI 兼容网关） |
| 模型 | `deepseek-account/deepseek-flash`（默认 `reasoning=high`） |
| 任务 | 从客服工单里抽取 `{问题类型, 紧急程度, 涉及产品}`（**全程固定**） |
| 评测集 | 20 条，作者手工标注 |
| 取值集合 | 问题类型 7 类 / 紧急程度 P0–P3 / 涉及产品 7 个（见数据集 `taxonomy`） |
| 采样温度 | 单次臂 `T=0.0`；Self-Consistency `T=0.7` |
| `max_tokens` | 3000 |
| 评分 | 三字段**全部命中**才算整条正确；另记字段级准确率 |

> ⚠️ **20 条、单人标注**。绝对值（比如"zero-shot 60%"）不要外推到线上；
> 能外推的是**范式之间的相对差值**，因为所有臂用同一批数据、同一个 rubric。

### 标注口径（不写清楚，数字就不可比）

1. 涉及产品取「业务实际被阻断的那一个」；短信/企微只是通道，通道故障算到用它的产品上（#1、#11）。
2. 一条工单有多个问题时取**最先阻断业务**的（#2 下游报表停是后果，不是产品）。
3. 用户自称"紧急"不算数，按 P0–P3 定义判。
4. 纯咨询（问能力/价格/流程/建议）一律归「咨询与售前」（#3、#9、#17）。
5. 用户**已给出绕过方案**就不算 P0/P1（#8 手动补发、#20 加个重试）。

## 三、逐范式：适用场景 / token 代价 / 失败模式

### 3.1 Zero-shot —— 本任务的性能地板，也是性价比天花板

- **适用**：值域封闭、判定规则能一次说清的分类任务。**本任务就属于这类**。
- **代价**：212 token / 724 ms，最便宜。
- **失败模式**：
  - **边界个案无锚点**。12/20 的错几乎全在「紧急程度」，因为它没有"什么算 P0"的**具体例子**，
    只能靠定义自己推 —— 而定义本身是模糊的（"资金风险"是否包含"已扣款未到账"？）。
  - 一旦字段值域扩大或规则变多，zero-shot 会先崩。

### 3.2 Few-shot —— 本任务的赢家，但**赢在示例怎么排，不是赢在示例有几个**

- **适用**：标签边界模糊、定义需要"用例子锚定"的任务。本任务正是。
- **代价**：391 token（≈1.8× A）/ 约 880 ms。**这是全表性价比最高的一档。**
- **关键发现：示例顺序的影响（+3 条）大于示例数量的影响。**

  B 和 C **用的是同一 3 个示例，只是倒序**，结果 13/20 → 16/20，差 3 条：

  | 条目 | B（原序） | C（逆序） | 翻转的字段 |
  | --- | --- | --- | --- |
  | #9 退授权 | ✗ 支付网关 | ✓ 智云控制台 | 涉及产品 |
  | #11 企微链接空白 | ✗ P1 | ✓ P2 | 紧急程度 |
  | #18 refund_amount 单位 | ✗ P3 | ✓ P2 | 紧急程度 |

  三个翻转**全部落在"最后一个示例附近"的语义上**。这是典型的**近因效应（recency bias）**：
  示例区末尾那个例子定义了模型的"默认锚点"。
  B 的末尾是 `咨询与售前/P3/数据同步服务`，模型整体被拉向"轻判" → #11、#18 判轻；
  C 的末尾是 `性能与可用性/P0/智云控制台`，模型被拉向"重判"，反而把 #11（P2）、#18（P2）判对。

  > **工程结论：few-shot 的示例顺序是超参，不是排版细节。**
  > 而且**方向依赖任务**：本任务上"末尾放最严重的那一档"更准。
  > 这不是可复用定律，是需要**为你的任务验一遍**的东西 —— 而这正是本次实验的意义。

- **换标签分布（D vs C）：15/20 vs 16/20，差 1 条。**
  C→D 翻转 3 条（#2、#11、#18 各有胜负）。说明分布也影响，但**幅度小于顺序**。
  这与直觉相反 —— 大家通常更担心"示例类别不均衡"，而实际更该担心"最后一个示例写什么"。

- **失败模式**：
  - **示例会传染错误口径**。示例错了，模型错得更整齐（比 zero-shot 更难发现）。
  - **示例里的字段组合会被照抄**。#9 在 B 臂被判成"支付网关"，就是因为示例里有
    `续费优惠码 → 支付网关` 这条强关联，模型把"授权退费"也套了进去。
  - 示例越多，prompt 越长，**边际收益递减且很快转负**（本例 3 个已接近饱和）。

### 3.3 CoT（显式提示）—— 本任务上**净亏损**

- **适用**：需要多步计算、多约束同时满足、或答案正确性依赖中间量（数学、逻辑、多跳检索）。
- **不适用**：**值域封闭的单步分类**。本任务就是反例。
- **代价**：token 5.1×、延迟 2.0×（相对 A）。
- **收益**：**0**（12/20 → 12/20，字段级还降了 0.017）。
- **失败模式（本任务实测）**：
  1. **过度升级**。#8（到达率下跌但有手动补发）、#10（报表显示 0）被判成 P0。
     一长篇论证，模型就倾向于把严重性说重。
  2. **改写而非推理**。E 臂的"理由"多数是 rubric 5 条规则的复述，没有落到这条工单的具体证据上。
     复述规则不产生新信息，只产生 token。
  3. **在推理模型上叠加是纯浪费**。见下节。

### 3.4 推理模型的「自带 CoT」—— 微弱正向，且**不能再叠 CoT 提示**

这是本题最值得记的一条，因为它和主流教程的说法相反。

| 对照 | 结果 | 解释 |
| --- | --- | --- |
| F vs A（开思维链 vs 关） | +1 条（12→13） | 微弱有效，但**延迟 2.3×**，性价比很差 |
| **G vs F（思维链 + CoT 提示）** | **−1 条（13→12）** | **叠加有害** |

机制（有 token 数据）：思维链从 539 字符涨到 1224 字符，但**准确率降了**。
多出来的部分是模型把自己的推理**用中文重讲一遍**，属于自我说服而非新增计算。

> **给推理模型的规矩：不要加 CoT 提示。**
> CoT 提示是给"没有思维链能力的模型"补课用的。给已经会想的模型再下"先想再说"的指令，
> 等于让它在想完之后再演一遍 —— 演的那一遍会引入偏差（本任务里是系统性地上调紧急程度）。
>
> 判定你的模型是不是"推理模型"，**不要看名字**，看三件事：
> ① 网关/metadata 有没有 `reasoning` 字段；② 响应里有没有 `reasoning_content`；
> ③ 同样的 prompt 下 `completion_tokens` 是不是远超输出文本本身（F 臂 172 vs 43 字符即可看出）。

### 3.5 Self-Consistency —— 有效但**不划算**（在本任务上）

用 C 的配置（实测最优）在 `T=0.7` 下采 5 次取多数投票：

| 指标 | 单次采样 | 5 次投票 | 增益 |
| --- | ---: | ---: | ---: |
| 整条全对率 | 0.73（73/100 个样本） | **0.75**（15/20） | **+2pp** |
| 字段级准确率 | 0.910 | 0.917 | +0.7pp |
| 成本 | 1× | **5×**（1954 token/条） | — |

**性价比结论：不值得。**

- **+2pp 在 20 条样本上只有 0.4 条的量级，落在噪声里**，不能算显著。
- 它**没有修好最难的字段**：「紧急程度」该错的还是错 —— 因为 5 次采样是**同一个模型同一个偏差**，
  投票只能消掉随机抖动，**消不掉系统性偏差**。而本任务的错误恰恰是系统性的（见 3.3 的过度升级）。
- 真要花 5 倍预算，**不如花在"换更强的模型"或"补 5 个高质量示例"上**，后者成本低得多且效果确定。

> **Self-Consistency 的正确适用条件**：错误主要是**随机性**导致的（比如多步算术算错一步）。
> 如果错误来自**模型对规则的理解偏差**，投票无能为力。

## 四、哪个范式赢，赢多少

**Winner：Few-shot（示例集 X 逆序），16/20 = 80%，字段级 93.3%。**

| 相对谁 | 赢多少 |
| --- | --- |
| vs Zero-shot | **+4 条 / +20pp** |
| vs CoT 提示 | **+4 条 / +20pp**（且便宜 5 倍 token） |
| vs 自带思维链 | **+3 条 / +15pp**（且快 1.9 倍） |
| vs Self-Consistency | +1 条，但成本只有 1/5 |

成本上：C 的 391 token vs I 的 1954 token，**用 1/5 的成本拿到更高准确率**。

**推荐配置（本任务）**：
```
reasoning = off            # 不加思维链，不加 CoT 提示
few-shot  = 3 个示例        # 末尾放"最严重/最容易误判"的那一档
temperature = 0.0
```
即 **A→C 这一条改动（换示例顺序）就拿到了全部收益**。

## 五、复用到别的任务时，先验什么

这套结论**只在"值域封闭的单步分类"上成立**。换任务时按这个顺序验：

1. **先测 zero-shot**，拿它当地板。（本任务 60%）
2. **加 3 个示例**，测两版顺序 —— 顺序必测，别假设。（本任务顺序差 3 条）
3. **确认模型是不是推理模型**（看 `reasoning_content` / `completion_tokens` 比值），
   是的话**别加 CoT 提示**。
4. **只有当前三步都撞墙**，再上 Self-Consistency —— 且先确认错误是随机的还是系统性的。
5. 全程盯 `finish_reason`，`length` 的样本**不计入准确率**，单独标注重跑。

## 六、已知局限

- **20 条样本、单人标注**。整条全对率的 1 条 = 5pp，**单条翻转不构成结论**，
  所以本文只把 ≥3 条的差异当信号（B→C 的 +3 条、G vs F 的 −1 条要谨慎看）。
- 只测了**一个模型**。`reasoning=off/high` 的结论依赖这个网关的实现，
  换模型必须重跑 —— 尤其"推理模型不该加 CoT"这条，换非推理模型会**反过来**。
- 标注口径是我自己定的（见"标注口径"节）。**换一个人标，金标会变**，
  尤其「紧急程度」这一列 —— 这也是本次最大的误差来源，值得后续做双人标注算一致性。
- 未测：示例数量 1/5/10 的曲线、CoT 提示的**强弱措辞**差异、JSON schema 强制约束（function calling）。
