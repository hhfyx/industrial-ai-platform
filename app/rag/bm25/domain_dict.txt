# 领域自定义词典（一行一个词，`#` 开头为注释）
#
# ## 什么时候往里加
#
# 判据只有一条：**jieba 默认会把它切碎，而它在本项目语料里是一个整体概念**。
#
# 不是"这个词重要"，也不是"这个词专业"。要加的是那些**切碎后会产生虚假匹配**的词。
# 例：`同轴光` 默认切成 `同轴` / `光`，于是它同时与含「同轴」的块、
# 含「光」的块产生匹配 —— 在 BM25 里这两类匹配都是有分数的，不是零。
#
# ## 为什么加完必须重建 BM25 索引
#
# 词典改的是 token 流本身。词典变了而索引没重建 → 索引里的 token 流是旧词边界，
# 查询用新词边界，两侧不一致。`make build-bm25` 会重切，所以改词典后跑一次就行。
#
# ## 加词的效果要能被验证
#
# `make bm25-audit` 会逐条检查：这里列出的每个词都必须**整体切出来**。
# 词典加错了（拼错字、写成一句话）会立刻红 —— 这条自检就是为下面那个坑加的。
#
# ## 文件格式（重要）
#
# **只允许两种行**：注释（`#` 开头）、词（一个词占一行）。
# **不允许在词表里写说明段落** —— 曾经的版本在文件末尾追加了一段 `>` 引用块，
# 结果 `load_userdict` 把整段话当成一个"词"加进了词典树，
# 而自检又把整段话当成"一个必须整体切出的词"，两边都错得莫名其妙。
# 说明写在这里（注释里），词只写词。
