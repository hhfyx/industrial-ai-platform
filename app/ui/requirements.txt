# Streamlit Community Cloud 部署依赖（**精简版**）
#
# ============================================================================
# ## 为什么这个文件放在 `app/ui/` 而不是仓库根（**W7 周一修正的关键点**）
# ============================================================================
#
# 这个位置不是随意的，是**被 Streamlit Cloud 的检索规则逼出来的**。
#
# 官方文档（App dependencies）原文：
#
#   > Community Cloud will use the first dependency file it finds.
#   > Community Cloud will search the directory where your entrypoint file is,
#   > then it will search the root of your repository. In each location,
#   > dependency files are prioritized in the following order:
#   >
#   >   uv.lock > Pipfile > environment.yml > requirements.txt > pyproject.toml
#   >
#   > Warning: You should only use one dependency file for your app.
#
# 本仓库根有 **`uv.lock`（1.1 MB）** —— 它在根目录里的优先级**高于**
# `requirements.txt` 和 `pyproject.toml`。所以：
#
# | 放哪里 | Cloud 会选谁 | 结果 |
# | --- | --- | --- |
# | 只有根目录的 `requirements.txt` | **`uv.lock`**（优先级更高） | 装完整依赖 → 含 torch 900 MB → **超时 / OOM** |
# | `app/ui/requirements.txt`（本文件） | **本文件**（入口目录先被搜） | 只装 12 个包 → 能跑起来 |
#
# **推论：根目录无法修复。** 除非删掉 `uv.lock`（但它是本地可复现性的依据），
# 否则根目录永远会命中 `uv.lock`。唯一可用的机制就是"入口文件所在目录"这一层。
#
# ### 曾经的错误做法（不要退回）
#
# 本文件原来叫 **`requirements-deploy.txt`**，而 deploy 文档写着
# "在 Cloud 的 Advanced settings 里指定这个文件"。
#
# **那句话是错的**：Advanced settings 里只有 **Secrets** 和 **Python version**，
# **根本没有"指定 requirements 文件"这个选项**。而 `requirements-deploy.txt`
# 不在 Cloud 认识的文件名列表里（只认 `uv.lock` / `Pipfile` / `environment.yml`
# / `requirements.txt` / `pyproject.toml`），所以它**从来就没被读过**。
#
# 当时的部署计划实际会命中根目录的 `uv.lock`，也就是"计划要装 12 个包，
# 实际会装 900 MB 的 torch"。这个错误在没人真正部署过之前**没有任何症状**。
#
# `tests/test_deploy_config.py` 现在守着这两条：文件名必须是 Cloud 认识的，
# 位置必须在入口目录。
#
# ============================================================================
# ## 为什么不装 torch
# ============================================================================
#
# Streamlit Cloud 免费层：
#
#   1. **1 GB 内存** —— bge + torch 实测占 561 MB，叠加框架开销会 OOM
#   2. **安装时长有限** —— 900 MB 的 wheel 经常超时
#   3. **磁盘配额有限**
#
# 所以部署侧**不含 torch / sentence-transformers**，
# 于是 `app/rag/embedding/bge.py` 的 `import` 会失败 → `get_embedder("bge-small-zh")`
# 报一句人话 → `deploy_config` 默认走 `hashing`。
#
# ## 这不是"阉割版"，是"明确的能力边界"
#
# 线上 demo 的能力 = 上传 + 索引 + 检索 + 流式 + 引用 + 拒答，**全部可用**；
# 只有"语义检索"这一项降级成"字面检索"。
#
# **把降级写在部署配置里，比让它悄悄 OOM 好得多** ——
# 前者用户能看到"当前为字面检索"，后者是"应用隔几分钟重启一次"。
#
# ## 如果要用 bge（付费层 / 更多内存）
#
#     RAG_EMBEDDER=bge-small-zh
#
# 并在这个文件里加上 torch + sentence-transformers。
# 那份 pyproject 已经写了（见 `[project] dependencies`），
# 复制过来即可 —— **不要手写版本号**，用 `uv export --no-hashes` 生成保持与本地一致。
