# W7 指标定义：公式 + 为什么 + 怎么刷 + 防刷

> 2026-11-30 定义，与命中口径一起冻结（见 [README.md](README.md) §九）。
> **写不出"怎么刷"的人，也写不出防刷的设计。** 每段第三栏最重要。
>
> 适用范围：`eval/questions-120.jsonl`（W7 报成绩集）。
> 调参集（`retrieval-gold` / questions-50）只做相对比较，不报绝对数。

---

## 一、Recall@k

**公式**：`Recall@k = 命中题数 / 可答题总数`，其中可答题 = fact + multi_hop。
命中口径见 README §九（fact：任一锚点进 top_k；multi_hop：两个锚点都进 top_k）。

**为什么**：回答"信息到底检不检索得到"。检索是链路第一层，这层不通，
后面精排、生成全是在垃圾上做优化——W6 周四的 Recall@50 天花板（62.5%）
一锤定音地改变了整周方向，就是它的价值。

**会被怎么刷**：
1. **增大 k**。Recall@k 对 k 单调不减，k=10 的数字永远 ≥ k=5 的——
   报 "@10 67.5%" 不算撒谎，但那是换了题量。
2. **把 gold 标得多而宽**。一条题标 5 个锚点，任一命中就算，
   分母没动分子凭空涨。

**防刷设计**：
- 头条数字**钉死 @5**（= 线上 `top_k`），k=1/3/8/10 只作附表；
- 锚点数按题型锁死（fact=1 / multi_hop=2 / refusal=0），
  `validate_golden.py` 强制，多标一个就报错；
- 每个锚点必须是**逐字唯一 quote**（20~60 字，全库恰落一块），
  "标得宽"在结构上不可能。

## 二、MRR

**公式**：`MRR = (1/N) Σ 1/rank_i`，rank_i 是第 i 条题**最靠后锚点**的排名
（多跳取两锚点中较大者——要看全两处，起决定作用的是晚出现那个）；
未命中记 0，分母仍是全部可答题。

**为什么**：Recall 只答"在不在"，MRR 答"排多前"。
阈值拒答机制只看 top1 分数，排名第 4 的命中对端到端毫无贡献——
W6 修过一次口径混用（recall_miss 按 top10 算、表头却写 @5），
同一份报告上下差 1 条，MRR 是防这类漂移的第二把尺子。

**会被怎么刷**：**选择性报告**。只报 fact 子集的 MRR（多跳天然低：
W6 实测 fact 0.31 vs multi_hop 0.07），把拉胯的那类藏起来。

**防刷设计**：
- 全量 MRR 与 by_type 拆分**必须同表出现**，只报其一视为无效报告；
- 分母写死"全部可答题"，未命中计入 0——不允许"在命中题内平均"
  （那种算法未命中越多 MRR 反而越高）。

## 三、NDCG@k

**公式**（二元相关度）：`DCG@k = Σ_{i=1..k} rel_i / log2(i+1)`，
`NDCG@k = DCG@k / IDCG@k`，rel_i ∈ {0,1}（排名 i 处是否为 gold 锚点块）。

**为什么**：诚实说明——本项目锚点只有 1~2 个、相关度是二元的，
NDCG 在这里与 MRR 高度重合，**不提供新信息**。纳入它的唯一理由是
与检索文献可比（RAGAS、BEIR 报的都是 NDCG），写简历/面试时能对上行话。

**会被怎么刷**：与 Recall 同源——加宽 gold、加大 k；
另外折扣底数（log2 vs loge）不写清，两份报告不可比。

**防刷设计**：
- k=5、log2、二元相关度三点写死在脚手架里，不作为可调参数暴露；
- 若某天相关度变成分级（比如"块部分覆盖 gold_answer"），
  必须先改本文件再改代码——分级标准本身就是可刷点。

## 四、Faithfulness（忠实度）

**公式**：`Faithfulness = 有引用支持的陈述数 / 答案陈述总数`。
实现口径沿用 `scripts/answer_quality.py` 已写死的判定表：
`invalid_refs` 非空一律 wrong（引用越界 = 不忠实，W4 的 F3），
不看结论对错。

**为什么**：检索命中 ≠ 答案可信。幻觉的本质是"说了引用里没有的话"，
W4 实测过：引用编号错了的答案，结论再顺滑也是毒——
它让"看起来有依据"变成不可核对。

**会被怎么刷**：
1. **用同一个模型当 judge 且判得松**——自我偏好：模型给自己
   生成的流畅答案打分系统性偏高；
2. judge 只看"读起来像不像有依据"，不核对**关键数字/单位/否定词**
   （"阈值 0.575" 判成 "0.575" 还是 "0.55"，"支持" 判成 "不支持"）。

**防刷设计**：
- **judge 与生成模型必须不同家族**（不同端点/厂商），写在运行记录里；
- judge 拿到的不是全文自由发挥：先**程序化抽取**答案与 gold_answer 里的
  数字、单位、否定词，逐项核对清单化，judge 只对清单项判"一致/矛盾"；
- 每次评测的 prompt/回答/引用/judge 原文**全部落盘**
  （answer-quality.json 已有此结构），人工可抽查审计。

## 五、Answer Relevancy（答案相关性）

**公式**：人工三档判定（沿用 answer_quality.py 判定表）：
`correct / partially_correct / wrong` 中的"答的是不是问的那件事"维度；
判为 wrong 的一种独立情形：**答非所问**（答案自洽但偏题）。

**为什么**：Faithfulness 管"说的有没有依据"，Relevancy 管"说的对不对题"。
一个答案可以句句有引用但答的是另一问——拒答题尤其依赖这个维度
（"语料没覆盖"式的正确拒答，答非所问的硬答都属于此类失败）。

**会被怎么刷**：judge 只看"像不像答案"——关键词沾边、
句式像标准答案就给 correct，不核对是否真的回应了问题。

**防刷设计**：
- judge 必须先**复述问题要求的那个事实**，再判答案是否包含它；
  复述不出来 = 这条判不了，记 `needs_human` 而不是猜；
- 抽检 20 条固定种子分层（fact 命中/未命中、多跳、拒答各有配额），
  人工复核比例不因"judge 都过了"而降为 0。

## 六、拒答准确率（三分类）

**公式**：三个数分开报，**绝不合成一个"拒答准确率"**：

| 类 | 判定 | 含义 |
| --- | --- | --- |
| 正确拒答 | refusal 题 top1 < 阈值 | 该拒的拒了 |
| 误拒 | 可答题 top1 < 阈值 | 库里有，却被阈值挡了 |
| 该拒不不拒 | refusal 题 top1 ≥ 阈值 | **库没有却硬答 = 幻觉** |

实现已在 `run_retrieval_eval.summarize()`：`refused_correctly /
false_refusal / false_accept`。误拒与"召回未命中"也是两件事
（top1 低于阈值才叫被拒；没进 top_k 是召回问题，归 Recall 管）——
W6 修过一个 bug：把 19 条检索未命中全算成误拒，读者会以为
拒答机制挡掉了 19 条真答案，实际挡了 0 条。

**为什么**：合数不可解读。30% 的"拒答准确率"可能是"全都不敢答"
（误拒爆炸）也可能是"几乎不拒"（幻觉爆炸）——两个方向相反的失败，
同一个数字。

**会被怎么刷**：**拒答集标错**。库里其实有答案的题被标成 refusal，
系统对它低分拒答 → "正确拒答 +1"，实为检索失败被计成拒答成功。
虚高无症状、不可从结果反查。

**防刷设计**：
- 每条 refusal 的 `notes` 必须留下**关键词全文搜索证据**
  （"关键词 X/Y/Z 全文 0 次"），`validate_golden.py` 强制检查
  notes 含此记录——没搜过就出不了题；
- 同领域约束（问 bge-m3 而语料只有 bge-small）保证低分来自
  "确实没有"而非"跨领域太容易"——跨领域题任何检索器都低分，测不出阈值；
- 报告里三分类**永远三个数并列**，任何一个缺失视为报告无效。

## 七、运行口径附则

1. **头条口径 = k=5 + 当前 HEAD 的 param/corpus 指纹**。指纹不一致
   （护栏变红）时的评测数字不许进报告，重跑索引后作废重来。
2. **答案质量两指标（Faithfulness/Relevancy）只跑抽检 20 条**，
   固定种子；全量 120 条 judge 一次的成本（80+ 次生成）不值得，
   检索指标才跑全量。
3. 网关不可用（如 11-05 的 502）时，两个生成侧指标记"未测"，
   **报告里不出现未经运行的数字**。
